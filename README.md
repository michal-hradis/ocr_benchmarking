# OCR Benchmarking

Compare OCR and handwritten text recognition (HTR) systems on **raster images of books, magazines and newspapers**, particularly complex and historical prints.

**Project status:** early implementation. Python project tooling, shared CPU/CUDA Docker base images ([setup](CONTRIBUTING.md#development-setup-and-commands), [Docker](docs/DOCKER.md)) and dataset manifests with a PAGE XML reader and validator ([datasets](docs/DATASETS.md)), the standardized prediction format with its validator and Markdown/HTML conversion ([predictions](docs/PREDICTIONS.md)), the Docker runner with per-sample execution records ([runner](docs/RUNNER.md)) and strict ordered and flexible (order-independent) CER/WER, bag-of-words and ROUGE-2 scoring of stored runs ([evaluation](docs/EVALUATION.md)) and comparison reports of evaluated runs in CSV, JSON and HTML ([reports](docs/REPORTS.md)) exist. Engine adapters exist for the [Tesseract CPU baseline](engines/tesseract/README.md), the [PaddleOCR PP-OCRv6 GPU pipeline](engines/paddleocr/README.md), the [PaddleOCR PP-StructureV3 layout pipeline](engines/ppstructurev3/README.md), the [PaddleOCR-VL-1.6 layout and VL document parser](engines/paddleocr-vl/README.md), the [Kraken historical OCR/HTR pipeline](engines/kraken/README.md), the [OCR-D/Calamari historical OCR pipeline](engines/ocrd-calamari/README.md), the [Surya OCR detector, recognizer and layout/reading order pipeline](engines/surya/README.md), the [docTR detector/recognizer baseline](engines/doctr/README.md) and the end-to-end image-to-text models [LightOnOCR-2](engines/lightonocr/README.md), [FireRed-OCR](engines/fireredocr/README.md) and [OvisOCR2](engines/ovisocr2/README.md), the [GLM-OCR 0.9B compact page OCR model](engines/glm-ocr/README.md), the page-image layout parser [Infinity-Parser2-Flash](engines/infinityparser2/README.md), the [MinerU2.5-Pro coarse-to-fine page parser](engines/mineru25-pro/README.md), the page-image to layout HTML model [Chandra OCR 2](engines/chandra-ocr2/README.md), the page-image to Markdown models [olmOCR-2](engines/olmocr2/README.md) and [DeepSeek-OCR-2](engines/deepseek-ocr2/README.md), the [HunyuanOCR-1.5 lightweight OCR model](engines/hunyuanocr/README.md), and the [PERO OCR offline page pipeline](engines/pero/README.md) with user-supplied model bundles; other engines are *not yet implemented*.

## Use cases

- **Newspapers:** full-page, multi-column, densely printed or degraded scans, potentially with 2,000+ text lines.
- **Books:** printed pages and historic typography, including text-dense scans.
- **Magazines:** pages with mixed text, headings, captions and complex layout.
- **Paragraph crops:** pre-prepared image crops, as an alternative dataset unit to the default **complete page**.

Input is always an **image**, never a PDF text layer. Ground truth uses **PAGE XML**. The benchmark will compare conventional OCR pipelines with page-image-to-text models; engine-specific resizing, segmentation and tiling belong to the engine. See [architecture](docs/ARCHITECTURE.md) for the separation between engines, reference data and evaluation.

For initial development, there is a **small, separately held set of page images with PAGE XML ground truth** (seven at present, referenced by [`datasets/dev-01.json`](datasets/dev-01.json)). It is not committed to this repository. Selecting or collecting additional evaluation datasets is **separate work, not part of the present backlog**.

## Planned outputs and scoring

Engines provide UTF-8 transcription plus versioned JSON with optional typed regions, optional lines and optional positions ([predictions](docs/PREDICTIONS.md)); native OCR outputs are retained. Strict ordered CER/WER, flexible CER/WER that tolerate column order and segmentation differences, bag-of-words precision/recall/F1 and ROUGE-2 are implemented. See [evaluation](docs/EVALUATION.md) for the metric families and the exact definitions.

## Quick start

`dataset validate|text`, `prediction validate|convert`, `run start|resume|status`, `evaluate` and `report` work today (see [datasets](docs/DATASETS.md), [predictions](docs/PREDICTIONS.md), [runner](docs/RUNNER.md), [evaluation](docs/EVALUATION.md#command-and-stored-scores) and [reports](docs/REPORTS.md)). The engines so far are Tesseract on the CPU ([build and run](engines/tesseract/README.md#build-run-and-evaluate); [presets](engines/tesseract/README.md#presets) with `tessdata_best`, German Fraktur and other segmentation modes need `make tesseract-best` and `--cache`), PaddleOCR on the GPU ([build and run](engines/paddleocr/README.md#build-run-and-evaluate), `make docker-cu130-paddle docker-paddleocr`; a [preset](engines/paddleocr/README.md#presets) detects pages up to 8000 pixels at full resolution), PP-StructureV3 on the GPU ([build and run](engines/ppstructurev3/README.md#build-run-and-evaluate), `make docker-cu130-paddle docker-ppstructurev3`), PaddleOCR-VL-1.6 on the GPU ([build and run](engines/paddleocr-vl/README.md#build-run-and-evaluate), `make docker-cu130-paddle docker-paddleocr-vl paddleocr-vl-model`, with `--cache`), Kraken on the GPU ([build and run](engines/kraken/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-kraken`), the OCR-D/Calamari pipeline on the CPU ([build and run](engines/ocrd-calamari/README.md#build-run-and-evaluate), `make docker-ocrd-calamari`, a standalone image with three historical model [presets](engines/ocrd-calamari/README.md#presets)), Surya on the GPU ([build and run](engines/surya/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-surya surya-model`, with `--cache`; the weights are under a research/personal-use [license](engines/surya/README.md#versions-and-licenses)), docTR on the GPU ([build and run](engines/doctr/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-doctr doctr-model`, with `--cache`; a [preset](engines/doctr/README.md#presets) detects at 2048 instead of 1024 pixels), LightOnOCR-2, FireRed-OCR, OvisOCR2, GLM-OCR, Infinity-Parser2-Flash, MinerU2.5-Pro, Chandra OCR 2, olmOCR-2, DeepSeek-OCR-2 and HunyuanOCR-1.5 on the GPU ([build and run](engines/lightonocr/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-lightonocr lightonocr-model`; [build and run](engines/fireredocr/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-fireredocr fireredocr-model`; [build and run](engines/ovisocr2/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-ovisocr2 ovisocr2-model`; [build and run](engines/glm-ocr/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-glm-ocr glm-ocr-model`; [build and run](engines/infinityparser2/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-infinityparser2 infinityparser2-model`; [build and run](engines/mineru25-pro/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-mineru25-pro mineru25-pro-model`; [build and run](engines/chandra-ocr2/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-chandra-ocr2 chandra-ocr2-model`, its weights under a modified OpenRAIL-M [license](engines/chandra-ocr2/README.md#versions-and-license); [build and run](engines/olmocr2/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-olmocr2 olmocr2-model`; [build and run](engines/deepseek-ocr2/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-deepseek-ocr2 deepseek-ocr2-model`; [build and run](engines/hunyuanocr/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-hunyuanocr hunyuanocr-model`, its weights under the Tencent Hunyuan Community [license](engines/hunyuanocr/README.md#versions-and-license); all ten run with `--cache`), and PERO OCR on the GPU with user-supplied bundles ([build and run](engines/pero/README.md#build-run-and-evaluate), `make docker-cu130-torch docker-pero pero-bundles`, also with `--cache`):

```sh
ocrbench dataset validate <dataset-manifest>
make docker-cpu docker-tesseract
ocrbench run start --engine engines/tesseract/engine.toml --dataset <dataset-manifest>
ocrbench evaluate runs/<run-id>
ocrbench report runs/<run-id> [runs/<other-run-id> ...] -o reports/<name> [--inspect]
```

Linux is the target platform, with per-engine Docker environments (shared CUDA/CPU bases where compatible, see [docs/DOCKER.md](docs/DOCKER.md)) and an RTX 4090 as a primary GPU test device. Consult [CONTRIBUTING.md](CONTRIBUTING.md) for the testing and PR policy.
